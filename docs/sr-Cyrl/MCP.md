# Коришћење стабла из AI модела (MCP)

> Превод оригинала [MCP.md](../../MCP.md) на српски.

`tools/mcp_server.py` је сервер за Model Context Protocol (MCP) за овај репозиторијум. Одговара на питања на која
одговара `tools/law.py`, а у сваком одговору наводи ограничења сваке евиденције. Користи само стандардну библиотеку
Python-а и git, чита репозиторијум и ништа не мења.

## Хостовани сервер: ништа не треба преузимати

Lexifina покреће овај сервер на адреси **https://global-law.lexifina.com/mcp** са учитаном сваком јавном земљом,
освежаваним из ових репозиторијума два пута дневно (у 03:00 и 15:00 UTC). Додајте га у било који MCP клијент који
подржава Streamable HTTP. Није потребан ни налог ни кључ. Његова прва адреса, `mcp.lexifina.com`, сада је MCP сервер
саме апликације Lexifina: клијенти подешени са њом треба да пређу на адресу изнад.

### Шта ради хостовани сервер

Има исте алате и даје исте одговоре као клон. Само чита и не чува сесију. Свака мрежна адреса сме да упути 60 позива
алата у минуту и 10.000 дневно, један по један и један позив алата по захтеву. Сваки одговор стиже у року од 95
секунди; позив коме треба више времена се прекида и каже како да се сузи. Сервер бележи који је алат позван и колико
је трајао, никада шта је питано.

- [Документација, ограничења и грешке](https://lexifina.com/api/global-law)
- [Питајте га у Lexifina-и](https://app.lexifina.com/law), без икаквог подешавања
- [API за право](https://lexifina.com/api/global-law), за позивање из вашег кода са Lexifina кључем који има
  дозволу Law (`law:read`)
- [Статус](https://status.lexifina.com)
- [Видео-записи](https://lexifina.com/watch) хостованог сервера и API-ја

Подесите га сами, као у наставку, да бисте радили без мреже или да би свако питање остало на вашем рачунару.

## Подешавање

Потребни су вам git и Python 3.9 или новији (довољан је и `python3` који долази уз macOS). Ништа друго не треба
инсталирати.

**Једна земља.** Цело стабло заузима много GB, али свака земља је посебан git подмодул, па можете преузети само право
које вам треба. За Румунију:

```sh
git clone --depth 1 https://github.com/lexifina/global-law && cd global-law
python3 tools/countries.py add romania
claude      # or open the folder in Cursor, VS Code or Codex
```

Прва команда преузима заједнички индекс свих земаља без права иједне земље, и без историје самог индекса, коју алати
никада не читају (видите одељак Start у README-у). Друга преузима само историју Румуније (око 1,7 GB на дан 4.
новембра 2026, неколико минута; већина земаља је далеко мања). Питајте о румунском праву и сервер одговара из ње;
питајте о земљи коју нисте додали и сервер ће вам рећи команду којом се она додаје. Додајте још земаља у било ком
тренутку (`python3 tools/countries.py add france spain`); сервер који ради види их у року од неколико секунди. На
Windows-у покрените скрипту са `py` или `python`.

**Све земље:**

```sh
git clone --recurse-submodules https://github.com/lexifina/global-law && cd global-law
claude
```

Клон садржи пројектну конфигурацију за сваки клијент, а све оне покрећу `tools/mcp.sh` преко git-а, који га покреће
из врха клона са POSIX љуском на свакој платформи (Git for Windows доноси једну) и бира први од `python3`, `python` и
`py` који је довољно нов:

| Клијент | Датотека | Прво покретање |
|---|---|---|
| Claude Code | `.mcp.json`, одобрен у `.claude/settings.json` | Када вас пита, означите фасциклу као поуздану; сервер и његови алати само за читање су тада дозвољени |
| Cursor | `.cursor/mcp.json` | Укључите сервер у MCP подешавањима ако га Cursor наводи као искљученог |
| VS Code (Copilot agent mode) | `.vscode/mcp.json` | Покрените га преко везе „Start“ у датотеци или из листе MCP сервера |
| Codex | `.codex/config.toml` | Означите пројекат као поуздан; Codex чита пројектну конфигурацију само у поузданим пројектима |

`AGENTS.md` (и `CLAUDE.md`, који га укључује) налаже агентима да на питања о праву одговарају овим алатима.
Да бисте сервер покренули ручно, `sh tools/mcp.sh` говори MCP преко stdin и stdout.

За поуздано окружење које држи код и податке у одвојеним клоновима, поставите `GLOBAL_LAW_ROOT` на апсолутну путању
Git клона који садржи `manifest.json` и git подмодуле корпуса. Python модули се и даље учитавају из сопствене фасцикле
`tools`; ово подешавање мења само корен података и репозиторијума. Неважећа путања се одбија при увозу.

Први одговор после покретања чита целу временску линију и набраја сваки корпус, што на пуном клону траје неколико
секунди. Сервер то ради чим се покрене, тако да је до тренутка када клијент нешто пита то обично завршено.

На великим корпусима (десетине хиљада комита и датотека) историја одредбе је `git log` ограничен на путању.
Уписивање графа комита сваког корпуса са филтерима измењених путања чини га око три пута бржим. Ово уписује само
git-ов сопствени индекс под `.git`, никада датотеке права:

```sh
git submodule foreach --quiet 'git commit-graph write --reachable --changed-paths'
```

Сваки други MCP клијент ради на исти начин: сервер говори JSON-RPC раздвојен новим редовима преко stdio. За пројектну
датотеку:

```json
{ "mcpServers": { "global-law": { "command": "git", "args": ["-C", "/path/to/global-law", "-c", "alias.global-law-mcp=!sh tools/mcp.sh", "global-law-mcp"] } } }
```

## Само неке земље

Сервер служи земље издвојене у вашем клону и, ако неке изаберете, само њих. `tools/countries.py` ради и једно и
друго:

| Команда | Шта ради |
|---|---|
| `python3 tools/countries.py` | Набраја свако право (body of law) у стаблу: служено, издвојено али неизабрано, или неиздвојено |
| `python3 tools/countries.py add romania` | Издваја га; git преузима само то |
| `python3 tools/countries.py only romania` | Служи само ова, издвајајући она која још нису ту |
| `python3 tools/countries.py only --all` | Поново служи свако издвојено право |

Назив је фасцикла земље (`romania`, `"united kingdom"`), ISO код (`ro`), ниво (`united-states/federal`) или путања
корпуса (`romania/national/acts`). За погрешно написан назив добија се предлог. `only` уписује
`global-law.jurisdictions` у сопствени `.git/config` клона, који се никада не комитује. Да бисте сузили сервер једног
клијента без мењања клона, поставите `GLOBAL_LAW_JURISDICTIONS` (називи раздвојени зарезима) у окружењу тог сервера;
он има предност.

Шта модел види:
- `list_jurisdictions` описује права која се служе, затим именује остала, зашто је свако изостављено (није издвојено
  или није изабрано) и команду којом се додају.
- Корпус који је издвојен али нечитљив на комиту који стабло пинује (прекинути клон још без комита, издвојена верзија
  која заостаје за пином после `git pull` без `git submodule update`, или плитки клон) такође се не служи. Сваки
  одговор над више корпуса именује га у реду „Left out:“ са командом која то поправља, као што ради `law.py world`, а
  путања или `jurisdiction` у њему добија ту команду као грешку.
- Одговор над свим јурисдикцијама (претрага, `laws_between`, `world_on_date`) завршава се са „Served here: N of the M
  corpora in the tree; the other K were not searched“ (бројеви за овај клон), како се „ништа није пронађено“ не би
  читало као да тога нема у праву.
- Путања или `jurisdiction` у изостављеној земљи добија грешку која именује команду за њено додавање.
  `resolve_citations` такав навод означава са `not served here`, а `find_provision` означава алијас који показује на
  њу.
- Упутства сервера налажу моделу да ту команду пренесе кориснику, а не да одговара из сећања.
- Сервер чији корисници не могу да додају корпус (хостовани) поставља `GLOBAL_LAW_HOSTED=1` у свом окружењу. Ниједан
  одговор тада не помиње `countries.py`: корпус који сервер нема је „not available on this server“, у
  `list_jurisdictions`, у напомени „Served here“, у грешци за путању или `jurisdiction` коју нема, у одговору
  `find_provision` за одлуку коју не може да пронађе, и у упутствима.
- `list_jurisdictions` са `jurisdiction` која се служи у целости не говори ништа о остатку стабла.

Историји одредбе потребан је само њен сопствени корпус, тако да су датуми, ауторство и историја исти са једном земљом
као и са свима.

### Судска пракса

Неки корпуси садрже судске одлуке, а не право: `switzerland/bund/caselaw` (савезни судови и тела) и
`switzerland/<canton>/caselaw` (судови сваког кантона), једна датотека и један комит по одлуци (`Kind: court`),
датирани даном када је одлука донета, са `Decided:`, `Published:`, `Court:`, `Docket:`, `BGE:`, `Source:` и по једним
редом `Cites:` за сваки члан савезног права који одлука наводи. `corpus.json` каже `"kind": "judgments"`. Заузимају
неколико GB, па их `countries.py add switzerland` не преузима: додајте их по називу (`switzerland/caselaw` за све
швајцарске судове, `switzerland/bund/caselaw`, корпус једног кантона, или `caselaw` за све).

- Одлука се чита као одредба: `read_law`, `who_wrote`, `compare_dates`, `provision_history`,
  `list_provisions`, и `law.py show`, `log`, `blame`, `words`, `diff` и `today` (исправка је посебан комит, а
  blame сваки ред приписује „court ruling, not a law“ или „correction“).
- Листе и претраге права (`search_law`, `laws_between`, `changes_between`, `search_changes`, `phrase_history`, `law.py
  laws`) изостављају судску праксу и то наводе у реду „Not read“, који броји судску праксу тражене јурисдикције и
  именује до три њена корпуса (`case_law_not_read_count`, `case_law_not_read`); `kind: "judgments"` чита само судску
  праксу, `kind: "all"` чита обоје, а `jurisdiction` која именује судску праксу чита њу. `world_on_date` и `law.py
  world` дају најновију одлуку сваког корпуса судске праксе; `world_on_date` прима `jurisdiction` и `kind`.
- Судска пракса се чита највише 60 s једног позива (`GLOBAL_LAW_CASELAW_SECONDS`): `search_law`, `phrase_history` и
  `search_changes` над многим судовима тада одговарају оним што су прочитали и именују изостављене корпусе („Partial:
  ...“). Највише половина језгара рачунара истовремено покреће `git grep`, сваки са највише 8 нити.
- `search_law` над многим правима не започиње ниједно ново чим остане мање од 25 s позива
  (`GLOBAL_LAW_SEARCH_MARGIN`), а бар једно је прочитано. Одговор је тада доња граница: текст почиње са „At least N
  provision(s) ...“ и има један ред „Partial: K of M bodies of law were not read within the time this answer may take
  (a, b, c ...); give a jurisdiction to read them.“; `page.total` је `null` уз `page.total_at_least`;
  `law_unread_for_time` именује првих 20 непрочитаних корпуса, редоследом којим би били прочитани, а
  `law_unread_count` каже колико их има (оба поља постоје само у таквом одговору). Корпуси се читају једним
  редоследом, тако да су прочитани они први, а `offset` наставља кроз њихове редове. Претрага једног корпуса се увек
  обавља у целости.
- Домаћин (host) који одржава индекс пуног текста данашњег текста може да га преда алату `search_law`
  (`mcp_server.search_index`, објекат са `counts(query, corpora, case_law)` и `paths(query, corpus, after, size)`;
  коментар изнад њега у `tools/mcp_server.py` је уговор). Индекс каже колико датотека сваког корпуса садржи речи и
  именује их редоследом путања; `git grep` затим чита само датотеке потребне за једну страну редова, а корпус без
  такве датотеке уопште не покреће git. Индекс се пита само за обичну претрагу текста на снази данас: `regex`,
  претрага са `case_sensitive`, претрага на прошли `date`, `jurisdiction` која је фасцикла унутар корпуса и сваки
  корпус који индекс изоставља претражују се grep-ом као и увек, а тако и све када индекс не одговори. Шта се
  разликује у одговору коме је индекс помогао:
  - `matched_by` је `"index"` (иначе поља нема).
  - `provision_count` је број из индекса и тачан је: одговор за њега не каже „At least“. Индекс поклапа речи као фразу
    целих речи, без обзира на велика и мала слова и дијакритике, док grep поклапа и делове речи („narcoti“ не налази
    ништа; `regex: true` користи grep). Такође броји датотеку у којој се фраза протеже преко прелома реда; таква
    датотека не даје ред. Одговор без поклапања каже „The words were matched as whole words. To match part of a
    word, pass regex true.“ (и у `hints`).
  - Редови су они које даје grep, истим редоследом, па `offset` наставља као и пре. Њихов укупан број није познат док
    део не стигне до последње датотеке: до тада је `page.total` `null` уз `page.total_at_least`, а текст каже
    „Showing lines A to B of at least N“.
  - Редови стижу корпус по корпус, тако да се корпус чита само када корпуси пре њега оставе места на страни: онај који
    долази после стране индекс броји, али се не чита (прва страна честе речи над свим јурисдикцијама чита прве
    датотеке првог корпуса). Укупан број редова је тачан у делу који чита последњу датотеку са поклапањем.
  - `provisions` набраја прочитане датотеке, а затим следеће које индекс именује, до 200, при чему непрочитани корпуси
    деле простор (пита се највише 30 њих, једним позивом када индекс има `paths_many(query, wanted)`); када садржи
    мање него што се поклапа, текст каже „The structured answer lists K of N matching provisions“.
  - Претрага свих јурисдикција (без `jurisdiction`) која ништа не пронађе не наставља ка белешкама о изменама, за шта
    би требало прочитати историју сваког корпуса; `related_changes` је тада празно. Претрага са `jurisdiction` то и
    даље ради, највише 1,5 s (`GLOBAL_LAW_CHANGES_HINT_S`): после тога одговор каже „The change notes were not read
    for this; search_changes looks there.“ (и у `hints`), а белешке о изменама судске праксе се у том времену не
    читају.
- Индекс наслова са којим `find_provision` поклапа речи чува се на диску за сваки корпус
  (`headings-v2-<corpus>-<commit>.json` у фасцикли кеша стабла, три најновија по корпусу), а индекс за нови комит чита
  само датотеке које се разликују од ранијег. Клон неколико земаља гради га при покретању, као и раније. Сервер свих
  земаља не гради ниједан док одговара: чита сачувани индекс где постоји (`store_heading_index` га прави, да би га
  домаћин позвао у позадини), а где не постоји, претражује наслове grep-ом. У меморији се држи највише 16 милиона
  наслова (`GLOBAL_LAW_INDEX_HEADINGS`); прво се одбацују корпуси који су најдуже некоришћени.
- Наводи из САД: `resolve_citations` чита сваки одељак листе или распона из US Code („11 U.S.C. §§ 361, 363(e), and
  364“, „9 U.S.C. §§ 1-16“), никада ознаку стране („USCA4 ... Pg: 3“) или цифру пододељка; навод по старијем
  нумерисању („11 U.S.C. § 110(e) (1976)“) пријављује се засебно, не повезује се са данашњим одељком; број предмета
  (docket) заједнички за више одлука разрешава се наводом, називом, годином или судом поред њега, или се означава као
  двосмислен уз првих пет; закон савезне државе (state statute) означава се као да га нема; иста одлука заведена два
  пута (`decision-relations.tsv`) разрешава се једном; одлука наведена на датум пре него што је донета то и каже, а
  датум који CAP даје само по месецу или години приказује се као такав.
- `check_precedent` чита надградњу (overlay) сваког служеног корпуса судске праксе, `judgments/<law
  corpus>/<provision>.jsonl` (на пример `judgments/switzerland/bund/acts/101/art-029.jsonl`), као и надградњу самог
  корпуса и стабла. Са много одлука проверава најновије (`max_results`), поредећи речи једном по верзији текста.
  Сваки ред именује датотеку одлуке (`decision`) и комит права на снази на дан одлуке (`law_commit`).
- `what_else_changes` додаје одлуке које наводе одредбу (број и последњих десет).
- `resolve_citations` и `find_provision` читају члан сваког швајцарског савезног акта по његовој званичној скраћеници
  на немачком, француском или италијанском (`Art. 336 OR`, `art. 29 al. 2 Cst.`, `art. 106 cpv. 1 CP`), из Fedlex-ових
  скраћеница у `data/swiss-aliases.json`; скраћенице које кантони користе за своје законе (`StG`, `KV`, `LPA`, ...) се
  не дирају. Одлука се проналази по референци BGE (`BGE 142 II 307`, `ATF`, `DTF`) или броју предмета (`4A_123/2024`,
  `A-1234/2020`, `BB.2020.123`), а `law_details` прима и једно и друго.
- `applies_to_case` над одлуком каже да је то судска одлука, а не закон.

## Како се чита датум

Евиденција сваке земље је њена сопствена git историја, а сваки комит у њој носи дан када је његова измена ступила на
снагу. Одредба на одређени датум чита се из њене сопствене историје, у историји коју стабло пинује на HEAD: од комита
који је дотичу, онај са најкаснијим датумом ступања на снагу на тај датум или пре њега, при чему у случају истог дана
побеђује каснији комит. Редослед комита није битан, јер земља може да дода старији акт после свог врха (tip).

Корпус који расте само додавањем (romania-law) поправља погрешну верзију тако што је поново дода: комит `Kind:
correction` са сопственим даном `In-force:` и `Corrects: <commit>` (текст је био погрешан) или `Re-asserts: <commit>`
(био је тачан и поново се наводи). То је обична верзија по горњем правилу, при чему каснији комит побеђује у свом дану,
приписана закону верзије коју понавља; `read_law` каже да се примењује исправка. Такве исправке може да пише
одржавалац (аутор `Lexifina`), чији су остали комити документација. Читају се још три његове врсте записа:
- **Премештања.** Комит који није закон и који преименује датотеке без њиховог мењања (премештање распореда у
  romania-law из новембра 2026, `codul-civil/` у `lege/2009/287/`) оставља свакој одредби једну историју под њеном
  тренутном путањом.
- **Повлачења.** Комит који није закон и који брише датотеке (`Withdraws: <act>`: акт који никада није припадао
  евиденцији) уклања верзије написане пре њега из евиденције за сваки дан.
- **Приписивања.** Када је погрешан био само приписани закон, `data/credits.csv` (`act,in_force,provision,law,...`,
  ознаке у `data/laws.csv`) именује закон коме се свака измена приписује; користе га `provision_history`, `read_law` и
  `who_wrote`.

Затим се, датотеку по датотеку, примењују исправке надградње (overlay). Комит исправке надградње носи `Kind:
correction`, `In-force: <first day>`, `Corrects: <act> <from>..<to>`, `Supersedes: <commit or none>`, `Reason:`,
`Act-path: <the act's folder or file>` и по један трејлер `Files: <path>` за сваку датотеку коју поставља. Његов текст
замењује обичну верзију сваке датотеке коју именује за сваки дан који обухвата његов распон, чак и када git не
показује никакву измену те датотеке (касно пронађена верзија може бити једнака тексту који врх већ има). Отворени
распон (`<from>..`) завршава се дан пре следећег обичног комита акта, следећег комита по датуму ступања на снагу који
дотиче `Act-path` (или, без њега, фасцикле његових `Files`). Најкаснија исправка која обухвата дан побеђује, а
`read_law` каже да се исправка примењује, шта замењује и зашто.

Исто правило важи за целу земљу на одређени датум (`search_law`, `list_provisions`, `changes_between`). Земља чија је
историја поређана по датуму ступања на снагу и без исправки чита се на свом последњем комиту на тај датум или пре
њега. Свака друга чита се као стабло верзија сваке датотеке за тај датум, које сервер гради у привременом директоријуму
објеката, никада у вашем клону. `tools/check_corpus.py` комите додате после комита са каснијим датумом (завршни
блокови) пријављује као упозорење: они су дозвољени. Временска линија преко земаља (`laws_between`, `world_on_date`,
`search_changes`) спаја историје земаља по датуму.

До 2. новембра 2026. стабло је такође писало по један датирани коренски комит за сваки закон који ступа на снагу, и
алати су их читали. Од тада стабло само помера пин сваке земље унапред (расте искључиво брзим премотавањем
(fast-forward), а репозиторијум земље може бити поново изграђен), тако да се његова коренска историја ту завршава.
Стари коренски комити сада служе само да датирају комит земље који нема сопствени датум.

## Како корпус описује сам себе

Сервер чита сваки корпус који стабло пинује. `manifest.json` их све набраја, а пише га `tools/describe.py` из
сопственог `corpus.json` сваког корпуса, или из `jurisdiction.json` и `data/repo.json` које испоручују репозиторијуми
заједничког градитеља (назив и код, са подразумеваним вредностима за остало), или из његове путање. Кодови прате ISO
3166: два слова земље, ISO 3166-2 код поделе (`US-CO`, `BR-BA`). Кодови испод првог нивоа (`AR-B-ALBERTI`, град у
провинцији Буенос Ајрес) граде се из кода родитеља и назива фасцикле и нису ISO кодови. Поља `corpus.json` која читачи
користе:

| Поље | Значење |
|---|---|
| `corpus` | ISO путања, `<iso2>/<level>/<kind>`, на пример `de/bremen/acts` (обавезно) |
| `name`, `language` | Шта је корпус, и његов језик по ISO 639-1 |
| `coverage` | Један ред о томе шта евиденција садржи, на пример „every Act in force since 1947“ |
| `history` | `in-force` (свака верзија од дана када је ступила на снагу), `current-only` (извор не чува прошле верзије), `replayed` (прошле верзије реконструисане применом сваког акта о изменама), `as-enacted` (сваки закон онако како је први пут објављен, без примењених измена) или `metadata-only` (каталошки уноси, без текста права). Декларишите га: репозиторијум без `corpus.json` декларише га у `data/repo.json`. Декларисана вредност се користи онаква каква јесте; само се недекларисана погађа из датотека изградње, а погађање може бити погрешно (текст издавача прочитан само као тренутни текст). Евиденција чија је свака верзија сопствени пречишћени текст издавача (`Compilation-id:` или `Consolidated:`) је `in-force`, а не `replayed` |
| `history_from`, `record_to`, `checked_on` | Где евиденција почиње, дан до ког је потпуна, дан када је последњи пут проверена |
| `record_note` | Све што читалац мора да зна о евиденцији |
| `in_force_trailer` | Трејлер који садржи дан ступања на снагу сваке измене (подразумевано `In-force`); `baseline_trailer` и `correction_trailer` ако се користе |
| `citation` | `{"file": "<regex over the corpus path with groups (folder, number)>", "cites": "<git grep -E pattern, {n} for the number>"}`; опционо `"numerals": "zh"` или `"ja"` (`{n}` је тада члан онако како га закон пише: 二百六十三条之一, 十六条の二), и `"not_followed_by"` / `"not_preceded_by"` (Python регуларни изрази које сервер проверава на сваком реду који git пронађе: git grep нема lookaround, а заграду CJK знакова чита као бајтове). Правило које сервер не може да користи се пријављује, никада се не замењује правилом другог распореда |
| `scope.default_reach` | Опционо: како измена досеже до предмета у току када обухват није забележен |
| `repeal_notice` | Опционо: регуларни изрази (један или листа) за ред који каже само да одредбе више нема, сопственим речима корпуса, додати уграђенима; `false` искључује обавештења о укидању за корпус |

Трејлери названи по дану (`In-force`, `Enacted`, `Made`, `Published`, `Corrected`, `Text-as-of` и слични) садрже датум
у облику YYYY-MM-DD; веза иде у `Source:` (или `Text-source:`). `Consolidated:` је канонски дан када је пречишћени
текст издавача ступио на снагу, са везом у `Source:`. Већина корпуса изграђених пре 4. новембра 2026. уместо тога је
уписивала везу у `Consolidated:`, а њихова историја не може да се мења, па читачи прихватају и једно и друго: датум
ту може да датира верзију (као `baseline_trailer`), а веза се наводи као извор верзије. `baseline_trailer` или
`correction_trailer` датира измену само када садржи датум.

Још четири записа мењају одговоре:
- **`Redates: <commit> [enacted] <YYYY-MM-DD>|no-date`.** Корпус који расте само додавањем исправља датум верзије без
  њеног преписивања: каснији комит носи по један ред `Redates:` за сваку верзију коју исправља (ред може да се
  понови), именујући комит изнад себе (у целости или префиксом од 7 или више знакова). Датум постаје дан ступања на
  снагу верзије, а за исправку надградње и први дан од ког се њен текст примењује (`Corrects: <act> <from>..`);
  `no-date` каже да извор не даје датум, па верзија закона постаје текст на дан који је забележен. `Redates: <commit>
  enacted <YYYY-MM-DD>|no-date` уместо тога исправља дан када је закон донет (вредност његовог трејлера `Enacted:`,
  `Adopted:`, `Made:` ..., који читачи приказују и по ком процењују сумњив датум), или каже да евиденција тај дан
  нема; његов дан ступања на снагу остаје. Читачи га примењују само када је аутор комита одржавалац, `Lexifina`; туђи,
  ред у другом облику или комит који није изнад њега се занемарује.
- **`Retroactive: yes; <provision>`.** Верзија је ступила на снагу пре него што је њен акт донет, како каже та
  одредба, па њен датум није означен као сумњив. На комиту `Redates:` обухвата сваку верзију коју тај комит поново
  датира. Вредност која не почиње са `yes` се занемарује.
- **`data/acts.json`.** `{"acts": [{...}, ...]}`, један ред по акту: `path` (фасцикла акта, `slug` у старијим
  корпусима), `status` (`in force`, `not yet in force`, `repealed`, `expired` или `annulled`), и дани `in_force`,
  `repealed`, `expired` и `annulled` у облику YYYY-MM-DD, са `repealed_by`, `expired_by` и `annulled_by` који именују
  закон или одлуку којом престаје. Читачи завршавају сваку датотеку под актом који је `repealed`, `expired` или
  `annulled` тог дана (поништење га завршава као укидање, а читач каже „annulled“), осим ако му је статус `in force`
  или `not yet in force`; без важећег дана кажу да је престао, али не и од када. Једно правило одлучује шта се дешава
  после краја, исто у `show`, `log`, `blame`, `words`, `diff`, `world`, претрази, `laws` и временској линији: верзија
  датирана после краја враћа датотеку на снагу само ако је њен закон донет (`Enacted:`, `Made:`, `Signed:` ...) на дан
  краја или после њега, ако није закон који је окончао акт (`repealed_by` га именује, званичним идентификатором или
  називом), и ако њен текст није белешка о укидању (`Norma derogada ...`, `(Derogada)`, `Norma anulada ...`,
  `[Repealed]`: белешка је поново наведен крај, а не поновно доношење). Свака друга каснија верзија никада не ступа на
  снагу, а ред `log` за крај је именује; закон чија ниједна верзија не ступа на снагу не наводи се у `laws`. Права
  каснија измена окончаног акта враћа његову датотеку, и `show` то каже. Исправка (`Corrects:`) престаје дан пре него
  што престане акт њене датотеке; она која почиње после краја примењује се тек када је каснија верзија вратила
  датотеку. `in_force` се наводи када се одредба тражи пре почетка евиденције.
- **Обавештење о укидању као текст.** Када издавач задржи број укинуте одредбе и штампа само да је више нема (шведско
  `16 § Har upphävts genom lag (2011:1252).`, грузијско `# მუხლი 26. (ამოღებულია)`, малтешко `Repealed by Legal
  Notice 99 of 2026.`, шпанско `(Derogado)`, немачко `§ 5 (weggefallen)`, румунско `Abrogat.`), верзија која садржи то
  обавештење окончава одредбу на свој дан, као што би то учинило брисање: `show` каже „repealed on <day> by <law>, the
  record keeps its repeal notice“ и наводи га, са излазним кодом окончане одредбе; `log` означава ред са `repealed`;
  `world` и стабла претраге изостављају датотеку; `diff` приказује уклоњени текст; `blame` и `words` се заустављају.
  Када је обавештење прва верзија коју евиденција садржи (евиденција само тренутног стања: свака шведска), `show` каже
  само „repealed“, јер евиденција не садржи ни текст ни дан укидања (обавештење именује закон). Каснија верзија са
  другим текстом је враћа. Правило је конзервативно: када се одвоје редови наслова, редови историје измена одредбе
  (`- Amended by: ...`) и цитиране уредничке напомене (`> Se deroga por ...`), сваки преостали ред (наслови, када ништа
  друго не остане; највише четири) мора бити број одредбе, затим реч за укидање на језику корпуса (`upphävts`,
  `ამოღებულია`, `repealed`, `deleted`, `derogado`, `suprimido`, `aufgehoben`, `weggefallen`, `abrogat`, `abrogé`,
  `ophævet`, `kehtetu`, `утратил силу` и друге), затим највише закон који је извршио укидање (`by ...`, `genom ...`,
  `por ...`, цртица или навод у загради): највише 40 речи, и без речи правила као што су „shall“ или „may“. Текст са
  било каквим правом поред обавештења (`1) Aufgehoben 2) Die Regierung ...`), реченица која укида други закон (`The X
  Act is repealed.`, `Genom lagen upphävs lagen ...`) или `(Sin contenido)` остаје текст. На дан 4. новембра 2026. ово
  је окончало 3.554 шведске, 1.517 грузијских, 1.345 малтешких, 6.650 шпанских, 465 лихтенштајнских и 30 науруанских
  одредби које су тог дана биле приказане као на снази; 148 од 148 ручно проверених обавештења била су обавештења, а
  1.400 других датотека чита се исто као и раније. Корпус додаје сопствене формулације помоћу `repeal_notice` у
  `corpus.json`. Белешке о укидању из правила о крају акта чита исти детектор; после краја акта довољно је да белешка
  само почиње као таква (`Norma derogada, excepto su art. 7 ...`). Градитељи би ипак требало да уклоне укинуту одредбу
  у комиту закона који је укида (са обавештењем, ако се задржава, као последњом формулацијом): правило чита већ
  написану историју.

`tools/check_corpus.py` проверава репозиторијум у односу на ово пре него што се пинује. Недостајући `corpus.json` је
упозорење када репозиторијум испоручује `jurisdiction.json` или `data/repo.json` (читачи тада за остало користе
подразумеване вредности), и броји се када се више корпуса проверава одједном (`python tools/check_corpus.py
<global-law checkout>` проверава сваки корпус издвојен тамо). `Redates:` или `Retroactive:` које би читачи занемарили
је упозорење (историја то не може да повуче; каснији `Redates:` може то да исправи), као и свака врста лошег реда у
`data/acts.json`, уз број; верзија на снази пре него што је њен акт донет оцењује се по дану акта, онако како га
`Redates: <commit> enacted` исправља; `acts.json` који не може да се рашчлани (parse) не пролази проверу.

Неке ствари читачи могу само да погађају, па их провера одбија (`FAIL: refused (<code>): ...`, излазни код 3; сваки
други неуспех излази са 1), а пин се не помера док се оне не поправе:
- `history`: декларисан `history` који није једна од пет горњих вредности, или `replayed` када свака датирана верзија
  именује сопствени пречишћени текст издавача (`Compilation-id:` или `Consolidated:`).
- `kind`: `Kind:` који читачи не познају (читали би га као закон). Користите реч коју `tools/law.py` познаје: `law`,
  `baseline`, `correction`, `uncredited`, `documentation`, и остале наведене у његовим табелама.
- `publisher`: верзија коју би читачи схватили као закон, али која је приписана издавачу (`publisher` корпуса, или
  назив који даје својим почетним текстовима). Припишите је закону који ју је створио, или је означите са `Kind:
  uncredited` (није именован закон) или `Kind: baseline` (почетни текст).
- `as-enacted`: у евиденцији декларисаној као `as-enacted`, текст закона дат као почетни текст или приписан издавачу.
  Припишите сваку верзију закону који она јесте (његов назив и број) и дајте јој `Kind: law`.
- `path`: назив фасцикле који носи „намештај“ са странице листе: бројаче прегледа или преузимања, или датум
  објављивања („...-18-april-2022-tahun-2021-137-views-105-downloads“). Они се мењају при свакој поновној изградњи, па
  би поновна изградња преименовала акт. Именујте фасциклу по броју, години и наслову акта, и преместите је једном у
  комиту документације.

Пошто историја не може да се мења, провере `kind`, `publisher` и `as-enacted` примењују се само на комите додате
после пина. Старији комити добијају упозорење. Корпус који никада није пинован проверава се у целости. Провере
`history` и `path` читају HEAD, па задржавају пин док се корпус не поправи.

У односу на комит који global-law сада пинује (`--pin`, или прочитан из global-law), `data/acts.json` не сме да
уклони крајеве аката без објашњења. Сваки акт који читачи окончавају на пину (као горе: укинут, истекао или поништен)
мора и даље бити окончан на HEAD, а онај окончан од одређеног дана мора и даље имати дан; акт чији су ред, дан краја
или статус окончања нестали, или чији је статус сада неки који читачи не познају (`as captured` у spain-law, што је
вратило 834 акта на снагу), не пролази проверу, а именују се прва три. Каснији дан краја није губитак. Када је
промена намерна (издавач поново наводи акт као на снази, или је крај забележен грешком), комит који мења
`data/acts.json` то каже у свом блоку трејлера са `Act-ends-reviewed: <why>`; то оправдава крајеве изгубљене само у
том комиту, а не у било ком комиту пре или после њега. Петља показивача (pointer loop) покреће ово пре него што помери
пин, тако да се такав комит не пинује док се не поправи или објасни.

## Алати

Да бисте прегледали велики корпус по актима, дајте алату `list_provisions` почетак назива фасцикле, на пример
`malta/national/acts/sl/586.` за сваки инструмент под малтешким Законом о заштити података (Data Protection Act).
Добијате по један ред за сваки акт, са његовим насловом и последњом изменом.

| Алат | На шта одговара |
| --- | --- |
| `list_jurisdictions` | Свака јурисдикција и свако право, докле досеже свака евиденција, колико одредби има и пример путање. Почните одавде. Садржи пуну напомену о томе шта евиденција не садржи (`record_limits`). Са `jurisdiction` набраја само корпусе те јурисдикције, без стабла свих земаља (`tree`), и без напомене „Served here“ када се сви служе. |
| `find_provision` | Путања одредбе по њеном броју („1182“, „Art. 16a“, „reg 13“), по популарном називу из `aliases.json` („Schuldenbremse“, „automatic stay“, „EHC plan“) или по теми пронађеној у тексту. Акт именован по наслову („Data Protection Act 2018“) је један ред, његова фасцикла (`kind: "act"`, са `title` и `files`), а не по ред за сваку његову датотеку; датотека која се поклапа по нечему више од назива акта задржава свој ред изнад њега. Назив акта са бројем одредбе („Equality Act 2010 section 4“, „Code du travail L3141-3“, „Ala. Code § 35-9A-421“, „Constitution article 4 section 5“) је та одредба (`read_as: "act and number"`): акт се проналази по наслову, скраћеници коју наслов даје, коду или фасцикли, а датотека по броју, врсте коју упит прво именује (section 2 пре schedule 2). Судска одлука се проналази по броју предмета или наводу, а тамо где домаћин има индекс одлука, и по називу („Miranda v. Arizona“, `read_as: "case name"`): одлуке које на почетку именују те странке, прво највишег суда, мишљење пре налога донетих на путу до њега; на назив који ниједна одлука не носи одговара се тиме, а не претрагом наслова. | `read_law` | (`include_text: false` за јефтину проверу датума, закона и извора.) Текст одредбе на одређени датум, са законом који ју је последњи изменио, следећом изменом, изворима за навођење и ограничењима евиденције. Каже да ли су речи и даље исте на крају евиденције (`latest`), и укратко набраја њене измене, од најновије (`history`: закон, датум ступања на снагу и комит за до 20 њих, уз `changes_count`). `in_force` је `true` или `false`, или `null` уз `in_record: false` и `record_starts` када је датум пре прве верзије одредбе у евиденцији, а та верзија је пречишћени текст, а не ступање закона на снагу: евиденција не зна, па програм не би требало да одговара. Додаје напомене „not the whole answer“ тамо где каснији закон сеже уназад преко датума, или где неки ефекат мења начин примене одредбе без мењања њених речи (`Modifies:`). **Више одредби у једном позиву:** `paths` (до 20 датотека), или фасцикла као `path` (акт: његове одредбе природним редоследом, првих 200). Њихови текстови долазе један за другим, сваки под редом `=== <path> (...) ===`, у деловима као један текст (`offset`, `max_chars`); `provisions` даје за сваку последњу измену, дужину и место у тексту, а напомене о евиденцији сваког корпуса долазе једном. Читање једне путање даје њену званичну везу и сваку напомену о њој. |
| `world_on_date` | Све јурисдикције на један датум: последња измена на снази у свакој, и следећа. *(Скривен у српском профилу; види напомену испод табеле.)* |
| `who_wrote` | Који закон је написао коју реч (или ред), са бројем речи по закону. Означени текст је у текстуалном одговору и у `marked` (`[n]` отвара низ закона са `mark` n у `laws`). | `laws_between` | Сваки закон који је ступио на снагу у одређеном периоду, укључујући и `start` и `end`, са бројем одредби које је сваки изменио. |

`global-law://law/{path}?date={date}&offset={n}` даје било коју одредбу онако како је на снази на одређени датум.

### Шта садржи одговор

Сваки одговор је текст (`content[0].text`) и исте чињенице као поља (`structuredContent`).

- **`summary` је наслов**: шта је пронађено (колико, на који датум, у ком обухвату) и, за одговор у деловима, где
  почиње следећи део. То није текстуални одговор: редови, текст права, напомене о евиденцији и свако упутство су
  засебна поља, па се ништа не шаље два пута. Клијент који чита само поља има `caveats` (напомене о евиденцији),
  `hints` или `notes` (упутства која текст даје речима: који алат боље одговара на питање, како су наводи пронађени),
  `explanation` (`applies_to_case`), `why` (`read_law` без текста), `not_searched_note` (корпуси које овај сервер није
  претражио) и `case_law_how`.
- **Аргументи се именују уједначено.** `jurisdiction` сужава сваки алат који прима обухват. `kind` је `laws` (`law` се
  чита исто), `judgments` или `all`; свака друга реч се одбија. `max_results` наводи своју подразумевану вредност и
  горњу границу у шеми сваког алата.
- **Периоди.** `laws_between` и `search_changes` укључују оба дана периода. `compare_dates` и `changes_between`
  пореде текст на `date_a` са текстом на `date_b`, и именују законе који су ступили на снагу после `date_a`, закључно
  са `date_b`.
- **Непрочитана судска пракса.** Листа или претрага права именује судску праксу коју је изоставила:
  `case_law_not_read_count` и до три корпуса (`case_law_not_read`), оне из тражене јурисдикције. Питање о Ирској не
  именује судове друге земље.
- **Шта евиденција не садржи** каже се једном по одговору, једном реченицом: „<corpus>: the text shown may not be the
  whole law that applied; this record does not hold changes to how a provision applies, commencement conditions or
  transitional rules.“ `list_jurisdictions` и упутства сервера дају пуно објашњење. Докле евиденција сеже и када је
  последњи пут проверена у односу на свој извор чини један ред („the record runs to ...; stale, last checked ... on
  ...“).

### Листе у деловима

`find_provision`, `search_law`, `laws_between`, `list_provisions`, `search_changes`, `phrase_history` и
`what_else_changes` примају `offset` (број редова које треба прескочити, подразумевано 0) и одговарају са `page`:

```json
"page": {"total": 238, "shown": 200, "offset": 0, "next_offset": 200}
```

`next_offset` је `null` у последњем делу. `total` је `null`, са доњом границом у `total_at_least`, када се претрага
зауставила пре него што је сазнала укупан број (судска пракса прочитана делимично, права непрочитана због времена,
или `find_provision` над много поклапања). Текст каже исто: „Showing files 1 to 200 of 238; pass offset 200 for the
next.“ Редови долазе истим редоследом при сваком позиву, тако да се делови не преклапају. Ранија поља остају (`count`,
`total`, `truncated`, `provision_count`). Ако је структурисана листа скраћена да би стала у одговор (`cut`),
`page.next_offset` је ред после последњег који још садржи. `what_else_changes` прескаче `offset` редова у свакој од
својих група, а `page.total` је његова највећа група. `read_law`, `compare_dates` и `who_wrote` деле свој текст на
стране по знаковима, као у наставку.

## Навођење званичног текста

Ово стабло је копија. Сваки одговор `read_law` почиње тиме где се сам закон чита и наводи: сопствена страница
издавача, затим прецизан навод (pincite, `Cite as:`). Структурисани одговор садржи исто као `cite`: `official_url`,
`shows` (шта та страница садржи), `pincite`, `version_url` (текст акта издавача који је тада био на снази), `law_url`
(закон иза верзије) и `archived_copies`. `resolve_citations` даје исто за сваки навод у тексту. Упутства сервера
налажу моделу да наводи ту страницу, никада овај сервер или његов репозиторијум.

| Издавач | `official_url` приказује |
|---|---|
| legislation.gov.uk | саму одредбу онако како је на снази на тражени датум (`…/ukpga/2014/6/section/42/2020-06-01`) |
| legislatie.just.ro (Румунија) | званични пречишћени текст акта на снази на тај датум, у ком треба пронаћи члан; сидра чланова на порталу нумерисана су по страни, а не по члану, па се не могу изградити из евиденције |
| fedlex.admin.ch (Швајцарска) | акт онако како је на снази од дана верзије (`…/eli/cc/1999/404/20210101/de`) |
| gesetze-im-internet.de (Немачка) | § или члан, онако како је на снази само данас; одговор каже када се то разликује од прочитаног текста |
| govinfo.gov (US Code) | одељак у најновијем издању, са јавним законом (Public Law) иза верзије као `law_url` |
| legislation.mt (Малта) | поглавље (Chapter) или инструмент онако како је на снази данас |

Везе се дају као везе издавача: архивирана копија из које је евиденција прочитана (web.archive.org) се „одмотава“ и
засебно наводи као порекло, а сопствени читач Lexifina-е (везе `Reader:`) никада се не даје као извор. Када евиденција
нема везу за верзију, одговор то каже уместо да понуди ово стабло.

## Дуге одредбе и дуги позиви

- **Дуги текстови долазе у деловима.** `read_law`, `compare_dates` и `who_wrote` дају највише <!-- fig:page_chars -->40,000<!-- /fig --> знакова текста
  одједном (око 10.000 токена; `max_chars` поставља од <!-- fig:page_least -->1,000<!-- /fig --> до <!-- fig:page_most -->100,000<!-- /fig -->). Дужи текст каже „Part: characters 0 to 39,958 of
  6,541,961. For the next part, call again with offset=39958“, а структурисани одговор даје исто као `text_part`,
  `word_diff_part`, `marked_part` или `lines_part`. Делови се завршавају на прелому реда или размаку. Једна шпанска
  уредба има 6,5 MB, а преко хиљаду датотека прелази 100 KB. `read_law` са `include_text: false` даје дужину
  (`text_chars`), тако да модел може да оде право на крај дугачког акта.
- **Остали одговори се заустављају на <!-- fig:answer_chars -->60,000<!-- /fig --> знакова**, на прелому реда, и кажу како да се питање сузи.
- **Ниједан позив не траје дуже од <!-- fig:call_seconds -->120<!-- /fig --> секунди**, било да време одлази на git или на сопствени рад сервера, као
  што је поређење верзија. Git процес који тада још ради се прекида (kill).
- **`who_wrote` остаје брз на дугим одредбама.** Приписује по речима до <!-- fig:words_max -->100,000<!-- /fig --> знакова, а по редовима (git blame)
  преко тога или када пролаз реч по реч траје дуже од <!-- fig:words_seconds -->30<!-- /fig --> секунди, и то каже (`fell_back`). Праћење речи враћених
  после престанка привремене измене прескаче се за дуге одредбе са много верзија, а иначе се зауставља после <!-- fig:restore_seconds -->20<!-- /fig --> секунди;
  одговор то каже (`traced`).
- **Сервер наставља да одговара док позив траје.** Позиви алата и читања ресурса извршавају се редом на радној нити;
  на све остало, укључујући `ping`, одговара се одмах. `notifications/cancelled` зауставља позив који именује: његов
  git процес се прекида, сопствене петље сервера се заустављају на следећој провери, и он не добија одговор.

## Протокол

Сервер говори обе ере MCP-а. Модерни клијенти (ревизија 2026-07-28) шаљу верзију протокола у `_meta` сваког захтева и
не треба им руковање (handshake); сервер одговара на `server/discover`, означава резултате са `resultType:
"complete"`, именује себе у `_meta` сваког резултата, даје наговештаје за кеширање у резултатима листања и читања, и
на неподржану верзију одговара грешком -32022 у којој набраја верзије које подржава. Старији клијенти (од 2025-11-25
уназад до 2024-11-05) почињу са `initialize` и опслужују се као и раније.

Јавни engine не открива профиле аутоматски и нема подразумеване вредности специфичне за јурисдикцију. Апликација може
да увезе `tools/mcp_server.py`, подеси метаподатке сервера, упутства и регистре алата/ресурса пре `main()`, и опционално
постави две функције. `prepare_tool_arguments(name, args) -> dict` ради после нормализације старих назива аргумената, а
пре провере шеме. `enrich_tool_result(name, text, data) -> (text, dict)` ради после алата, а пре додавања општих
напомена о покривености. Подразумеване функције нису постављене, па јавни stdio покретач увек покреће генерички engine.

## Безбедност

Сервер је само за читање и локалан. Чита git репозиторијум у ком се налази, никада не користи мрежу и никада не
покреће љуску (shell), тако да нема порт који би се могао напасти и ништа не кошта по позиву; сваки корисник покреће
сопствену копију преко stdio. Ништа не уписује осим ако не поставите `GLOBAL_LAW_AUDIT_DIR`. Тада тамо у
`global-law-mcp.jsonl` додаје по један ред за сваки позив алата, са временом, алатом, кључним хешом (HMAC-SHA-256)
аргумената, трајањем и статусом. Сами аргументи се никада не уписују. Кључ је нов за сваки процес, или
`GLOBAL_LAW_AUDIT_KEY` ако желите да се понављања поклапају између сесија; без кључа би се кратки аргументи, као што је
датум, могли повратити хеширањем претпоставки. Сваки git позив је листа аргумената, при чему се свака корисничка
вредност прослеђује као вредност (`-e`, `--`), тако да се ништа што клијент пошаље не покреће као команда или опција.

- Путање морају остати унутар стабла: без `..`, апсолутних путања, ознака дискова, двотачки или џокер-знакова.
- Хешеви комита морају бити хексадецимални, а `law_details` чита само комите у историји коју стабло пинује, никада
  другу грану или недоступан нацрт у клону одржаваоца.
- Текстуални аргументи ограничени су на <!-- fig:text_limit -->300<!-- /fig --> знакова, осим текста који чита `resolve_citations`
  (<!-- fig:brief_limit -->50,000<!-- /fig --> знакова), и ниједан не сме садржати контролне знакове. Аргументи које шема алата не именује се
  одбијају, као и идентификатори који нису стрингови или цели бројеви.
- Регуларни израз који даје модел покреће само git, никада Python-ов механизам са враћањем (backtracking). Обрасци који
  би и даље могли трајати експоненцијално дуго се одбијају: поновљена група која садржи квантификатор, алтернацију или
  другу групу, или повратна референца (back-reference).
- Git никада не покреће филтер за конверзију текста или спољни драјвер за разлике (`--no-textconv --no-ext-diff`), чак
  ни када атрибути издвојене верзије именују неки који дефинише ваша git конфигурација.
- Сваки позив алата има укупно <!-- fig:call_seconds -->120<!-- /fig --> секунди, у git-у и у сопственом раду сервера, после чега се зауставља и то
  каже. Клијент може да откаже позив, а сервер одговара на друге захтеве док један траје. Дуги текстови долазе у
  деловима. Листе су ограничене и кажу када су скраћене. Претраге не прегледају више комита него што приказују, а
  `resolve_citations` проналази највише <!-- fig:citations_limit -->100<!-- /fig --> одредби.
- Клијент који престане да чита не може да одржава сервер у раду: прекинута цев (broken pipe) одбацује преостали
  посао, а после затварања stdin одговор заглављен <!-- fig:stuck_seconds -->10<!-- /fig --> секунди окончава процес.
- Порука је ограничена на <!-- fig:message_mb -->1<!-- /fig --> MB. На бајтове који нису UTF-8, JSON угнежден превише дубоко и бројеве предугачке за
  читање одговара се грешком рашчлањивања (parse error). Корпус који није издвојен, или није читљив на свом пину,
  сужава одговор и бива именован; не зауставља сервер. Интерна грешка пријављује само свој тип, а детаљи иду на stderr.
- Текст права, белешке о изменама и белешке о пресудама прослеђују се као подаци. Упутства налажу моделу да они никада
  нису упутства.
- Тестови укључују скуп за непријатељски унос и случајеве које је пронашла независна ревизија (октобар 2026), сваки
  сада као тест. Fuzz покретање са 400 насумичних позива није дало ниједан пад, ниједну интерну грешку и ниједан
  процурели детаљ.

## Шта рећи кориснику

Покривеност је делимична. Сваки корпус садржи само право које његов опис именује, за наведени период, па „ништа није
пронађено“ значи да у евиденцији нема ничега. Сваки одговор носи напомене када датум пада пре почетка или после краја
евиденције; пренесите их. Датуми су датуми које свака евиденција даје измени: дан када је ступила на снагу, или за прву
верзију дан када је донета. `applies_to_case` користи обухват који евиденција садржи, као податак (`Applies:`) или у
речима белешки о изменама, и каже које од тога. Када обухват није забележен, каже да досег до предмета у току није
забележен и именује подразумевано правило корпуса (за САД, претпоставку против ретроактивности), не одлучујући о томе.

## Поређење са другим MCP серверима за право

Проверено 28. октобра 2026. у односу на објављене описе сваког сервера:
- legalize-mcp и lawyer-mcp (корпус legalize.dev)
- legislation-gov-uk-mcp и uk-legal-mcp
- law-scrapper-mcp (Пољска)
- MCP сервер CourtListener-а и court-listener-mcp
- MCP сервер GovInfo-а
- LexAPI и mcp-eu-sparql (ЕУ)
- Open Legal Data и de-eli-mcp (Немачка)

Неколико њих чита текст закона на одређени датум и пореди верзије (legalize.dev, сервери за законодавство УК).
Ниједан од њих не нуди:
- ауторство по речима
- када су речи ушле у право или га напустиле
- до којих предмета измена досеже (`applies_to_case`)
- шта се још ослања на одредбу
- засебне датуме ступања на снагу, доношења и објављивања. Бирање верзије по датуму не говори да ли је она била на
  снази; сам legalize.dev на то упозорава.

Где су други испред:
- **Покривеност.** legalize.dev има 32 јурисдикције; сервери за УК имају целокупно законодавство УК.
- **Ажурност.** Токови измена (change feeds) и измене у поступку.
- **Судска пракса.** CourtListener, Open Legal Data и uk-legal-mcp имају судску праксу са мрежама навода и „cited
  by“. Ово стабло садржи одлуке судова неколико земаља, сваку са надградњом одредби које њене одлуке наводе (коју чита
  `check_precedent`), али још без навода између одлука.
- **Историја парламентарног поступка.**
- **Хостовани приступ.** Неки раде као хостовани сервери са OAuth-ом, док се овај покреће локално из клона.

## Тестови

```sh
python -m unittest tests.test_mcp -v
```

Тестови разговарају са сервером онако како то ради клијент: руковање (handshake), сваки алат, грешке, ресурси и
правила о примени сама по себи. Сервер је такође тестиран „на слепо“, у четири круга: модел коме су дати само ови
алати тачно је одговорио на 26 од 26 питања, укључујући и непријатељска, и рекао је где евиденција не може да
одговори.
